# DeepSeek 轻量传输实现与内存验证

日期：2026-11-12。

本文保留第一阶段 DeepSeek 实验和测量。后续已完成统一 HTTP 替代并移除 LiteLLM，当前实现见[共用轻量模型传输与供应商差异配置方案](shared-lightweight-provider-design.md)。下述历史测量不能当作统一替代后的新内存实测。

## 第一阶段实现范围（历史）

明确配置 `provider=deepseek` 的请求使用 `DeepSeekAdapter`（httpx + SSE），覆盖聊天、划词、图片、工具生成及多模型咨询。其他供应商保留 LiteLLM 兼容路径；安装包中的 LiteLLM 依赖尚未删除。切换到其他供应商后仍可能加载并常驻。

启动仅检查依赖的模块规格，不为检查而导入 OpenAI 等 SDK。DeepSeek 跳过 LiteLLM 后台预热；其他供应商沿用已有预热。HTTP 客户端按网关生命周期延迟创建、复用连接池，退出或结束短期任务时关闭。不发送预热模型请求。

传输保留已有的消息、图片、DeepSeek thinking 禁用参数和工具定义。重试、限流、脱敏及 token 记录仍由统一网关负责；多模型咨询不再绕过网关。无 usage 时保持未知；没有明确的服务商收费字段，不推算实际费用。

## 协议边界

- 不根据 URL 或模型名猜测协议，不在请求失败后自动换路线，避免重复请求和计费。
- 自定义 API 基地址沿用原路径；默认文本与图片分别使用 DeepSeek 根地址和原有 `/beta` 地址。
- SSE 支持跨网络块的 UTF-8、CRLF、保活注释、跨行 data、尾随 usage 帧、推理内容及并行工具参数分片。
- 必须收到有效结束原因和 `[DONE]`。异常断流、空回答、无效 JSON、工具参数缺失/错误或工具调用被截断均报错；验证所有工具调用后才向 Agent 提交。
- 文本输出后不重试整个请求；取消关闭对应响应，连接池供其他请求继续使用。请求期限会关闭只返回保活消息的流。
- 自定义地址不能嵌入账号、查询参数或片段；不跟随重定向发送认证信息。

## 受控内存比较

同一 Python 环境、同一份当前代码，各启动三个新进程，使用 Windows PSAPI 测专用工作集和专用提交量。旧路线模拟原入口提前导入依赖并加载 LiteLLM；新路线加载 DeepSeek HTTP 客户端，包含主聊天与划词两个客户端。两边均初始化分词器、OCR 和空主窗口。

探针使用临时配置、临时数据库、offscreen Qt；禁用系统快捷键、托盘、便签恢复和用户脚本，阻止网络连接。执行一次相同的合成 720p OCR 后再次采样。未读取供应商密钥，未调用模型。

下表为三次中位数，单位 MiB；两类内存不能相加。

| 阶段 | 旧路线专用工作集 | 轻量路线专用工作集 | 差额 | 旧路线专用提交 | 轻量路线专用提交 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 空主窗口、OCR、模型运行时及客户端就绪 | 249.52 | 152.09 | 97.43 | 611.56 | 513.46 |
| 一次 720p OCR 后 | 262.64 | 162.79 | 99.85 | 624.79 | 524.80 |

客户端就绪时，旧路线工作集范围 248.41–250.82 MiB，新路线 151.60–152.36 MiB。新路线三次均确认 `litellm`、`openai` 不在已导入模块中。

这证明了当前依赖加载路径的差异，不等于真实用户进程必定降低同样数值。真实数据、屏幕缩放、操作历史与系统内存压力均有影响；之前真实进程与空界面实验间的差额仍未全部归因。已经运行的进程不会因源码变化卸载旧模块，需要退出后重新启动 Nemo。

原始探针、六份采样 JSON 和回归日志保存在本地忽略目录 `artifacts/`。这些测量不包含真实服务商连通性、服务端响应速度或长期运行的泄漏结论；后续按[内存优化方案](memory-optimization-plan.md)继续验证。
