# 用量与账单（原自定义定价说明）

自 2026-11-12 起，普通应用不再读取或生成 `config/model_pricing.json`，也不再使用 LiteLLM 内置价格表估算费用。用户无需填写或维护价格。

运行记录继续保存模型、输入/输出/缓存 token、耗时与每次尝试的状态。金额遵循以下规则：

- 服务商未明确返回费用时，显示“服务商未返回费用”，不显示为零。
- 适配器只有在上游协议明确提供费用及币种时，才可返回 `provider_cost={amount, currency}`。SDK 的 `_response_cost`、单价和自行计算的金额不能作为服务商账单。
- 当前轻量协议适配器没有映射经确认的服务商实际费用字段，因此通常只显示 token 用量和账单提示。本次没有增加自动查询账户账单的后台请求。
- 已返回金额按币种分别汇总，只覆盖当前运行关联的调用；最终扣费以实际服务商账单为准。
- 已知官方 API 端点提供服务商控制台链接，仅在用户点击时打开。自定义代理、中转、未知端点和缺少端点来源的旧记录不推测账单地址，应自行前往实际服务商的账户控制台。

旧记录中的金额保留并标注为“历史估算（非账单费用）”，不会改成实际扣费、重新计算或混入服务商返回金额。旧价格文件留在磁盘但不再使用。

数据库升级至 V4，升级前备份，新增服务商费用、币种和经校验的控制台地址字段。脱敏诊断保留 token 和服务商返回金额，默认不再导出历史估算及定价来源。

开发者独立运行的 `evals/` 也采用相同原则：不维护价格、不根据 Token 估算金额，只汇总服务商明确返回的费用并按币种展示。旧配置中的 `pricing` 必须移除；缺少费用保持未知。target 与 Judge 分别记录用量与金额，最终扣费请到实际服务商官网账单查看，不自动查询账户账单。历史评估文件保持原样，估算字段不代表实际扣费。详见 [独立评估说明](../evals/README.md)。
