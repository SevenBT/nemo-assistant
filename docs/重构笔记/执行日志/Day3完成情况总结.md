### 讲稿 2：技术深度（"曲线 B"四问）

**核心内容**：4 个技术深度问题，每个 2 分钟

**问题 1：为什么已流出内容不能重试？**
- 问题背景：流式 + 重试的矛盾
- 具体场景：红烧肉例子
- 技术约束：LLM 无状态 + 随机性
- 解决方案：反向不变量 + 标志位
- 测试守护：模拟网络断开

**问题 2：生成器 yield 顺序 bug**
- Bug 现象：token 数为 0
- 排查过程：5 步定位
- 问题根源：消费者 break 后生成器挂起
- 为什么只影响部分厂商：usage 帧位置不同
- 解决方案：finally 块保证执行

**问题 3：WRAP_UP 设计动机**
- 问题背景：需要停止信号
- 常见方案的问题：外部强制停止
- WRAP_UP 设计：内部主动停止
- 效果：95.7% 正常停止
- 兜底策略：3 层（提示词强化、最大回合数、用户手动停止）

**问题 4：为什么 tool_calls 要计入 token？**
- 问题背景：工具调用占 token
- 具体例子：天气查询（低估 62.5%）
- 解决方案：message_to_token_text()
- 验证结果：误差 50% → 5%

**准备了**：
- 每个问题的 30 秒速答版本
- 追问应对策略
- 关键话术标记

### 讲稿 3：问题解决（STAR 法则）

**STAR 结构**：
- S - Situation（情境）：15 秒
- T - Task（任务）：15 秒
- A - Action（行动）：60 秒（重点）
- R - Result（结果）：10 秒

**准备了 4 个案例**，每个 2 分钟：

**案例 1：笔记查找 NameError**
- 偶发性 bug（有时能用，有时崩溃）
- 5 步排查：错误栈 → 上下文 → 初始化流程 → 配置对比 → 修复
- 问题根源：条件初始化 + 假设存在
- 解决方案：空对象模式 + 单元测试

**案例 2：工具生成死循环**
- 连续调用相同工具 10+ 次
- 6 步排查：复现 → 检查历史 → 打印响应 → 检查提示词 → 优化 → 加检测器
- 问题根源：提示词不清晰
- 解决方案：优化提示词 + 死循环检测器

**案例 3：快捷键保存不生效**
- 快捷键无效，按钮正常
- 7 步排查：复现 → 检查绑定 → 加日志 → 检查逻辑 → 复现流程 → 打印值 → 修复
- 问题根源：中文输入法候选框未确认
- 解决方案：允许保存空文件 + 弹窗确认

**案例 4：日志全部丢弃**
- 日志文件为空
- 7 步排查：检查配置 → 测试日志 → 检查初始化 → 检查 clear() → 检查返回值 → 全局搜索 → 修复
- 问题根源：多次初始化 + 清空 handler
- 解决方案：单例检查

**准备了**：
- 每个案例的 30 秒速答版本
- 选择策略（根据面试场景）

### 讲稿 4：技术选型

**回答框架**：
1. 需求背景（15 秒）
2. 候选方案（30 秒）
3. 对比分析（45 秒）
4. 实际效果（15 秒）

**准备了 3 个技术选型**，每个 2 分钟：

**选型 1：为什么用 LiteLLM？**
- 需求：支持多厂商 API
- 候选：官方 SDK、LangChain、LiteLLM
- 选择理由：统一接口、自动处理差异、社区活跃
- 实际效果：省事 + 唯一的坑（usage 提取不完整）
- 风险兜底：抽象层隔离 + pin 版本

**选型 2：为什么用 tiktoken？**
- 需求：精确计算 token
- 候选：字符估算、API count_tokens、tiktoken
- 选择理由：快（<1ms）、准（误差<5%）、兼容性好
- 实际效果：准确率 60% → 95%+
- 对比 transformers：太重（500MB+ vs 2MB）

**选型 3：为什么用 LLM-as-Judge？**
- 需求：评估语义质量
- 候选：人工评估、规则评分、LLM-as-Judge
- 选择理由：可规模化、稳定性可控、成本可接受
- prompt 设计：维度分解、5 分制、few-shot、温度=0
- 实际效果：发现了规则评分发现不了的问题
- 偏见问题：长度偏见、模型自我偏见（双 Judge + spot check）

**准备了**：
- 候选方案对比表模板（面试时可以画）
- 追问应对（不知道的技术、技术调研方法、技术选型的坑）

## 💡 关键提醒

### 讲稿使用原则

**不要背稿**：
- ❌ 逐字逐句背下来（会显得机械）
- ✅ 记住结构和关键点（自然表达）

**灵活调整**：
- ❌ 面试官打断还继续讲（不懂变通）
- ✅ 根据面试官反应调整（看兴趣点深入）

**自然表达**：
- ❌ "根据我准备的讲稿……"（太刻意）
- ✅ "我举一个印象最深的例子……"（自然引入）

---

### 时间控制技巧

**5 分钟版本**：
- 看面试官：如果频繁点头 → 继续
- 看面试官：如果看表/看手机 → 快速收尾

**30 秒速答**：
- 面试官说"简单介绍一下" → 用 30 秒版本
- 面试官说"详细介绍一下" → 用 5 分钟版本

**2 分钟版本**：
- 面试官时间有限 → 用 2 分钟版本
- 面试官说"控制在 2-3 分钟" → 用 2 分钟版本
